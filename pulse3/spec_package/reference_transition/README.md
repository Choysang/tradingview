# 排名预算连续性：有限参考

本目录只证明**试用排名权重的残余归属**，不分配资金、不生成委托、不计算收益、不实现评分校准，也不增加公共 API 或第二本账。

## 两个不同入口

`allocate_trial_ranking_budget` 接受基线身份、已批准的候选绝对份额和当次有资格运行的候选集合。所有权重必须为有限且非负的 `Decimal`，不接受 float、int 或字符串。所有已批准候选的合计不得超过 `trial_total_cap`，默认 `Decimal("0.1")`。此上限是整个试用池的总预算，不能解释成每个候选各有 10%。

一个候选获准 10% 时，它始终占 10%；剩余 90% 归基线。候选失效时，其原份额回到基线，不分给其它候选。结果保留失效候选的零权重，`returned_to_baseline` 单独表示退回的已批准份额。未分配的原始预算也归基线，但不记作“退回”。

候选不得与 `baseline_id` 相同；资格集合不能包含未获预算的候选。基线不可用且残余为正时抛出 `BaselineUnavailable`，不返回可发布结果，也不重归一剩余候选。上层应显示缺供、使用另一个已经批准的连续性政策或停止该次新榜发布，不能把旧榜假称最新。

`activate_approved_primary_ranker` 表达**另行批准的 100% 主干替换**。它要求调用方提供已核实批准记录的引用和当前资格；这只是有限参考中的来源记录，不是身份认证或审批服务。试用入口的 cap 必须小于 1，不能通过传入 1 绕过完整替换入口。成为试用、基线故障、排名领先都不会自动调用替换入口。

## 精度与边界

候选原始份额保持原值。求和与残余计算按输入所需精度使用局部 Decimal 上下文，避免调用方设置较低精度后把极小超额四舍五入掉。权重只表示统一目标下的排名预算；预测分数如何校准、特征缺失与弃权如何解释、主干是否有证据准入，都由外部明确合同决定。

示例：a 获准 0.04、b 获准 0.06，但 b 当次失效，结果为 a=0.04、b=0、baseline=0.96；不会把 a 放大到 1，也不会把失效 b 的份额移给 a。

## 运行必要测试

在交付包根目录运行：

```bash
python -m unittest discover -s reference_transition -p 'test_*.py' -v
```

测试覆盖零/单个/多个候选、候选失效、基线故障、10%不被放大到100%、超总预算、非法数值/类型、同ID、未批准资格、低精度调用上下文及独立的完整替换入口。

这些测试仅证明上述排名预算语义，不证明完整生产评分、策略收益、审批、数据库事务或资金账本已经实现。
