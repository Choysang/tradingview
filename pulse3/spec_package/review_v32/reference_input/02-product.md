# 02 · 产品规格

> 本卷回答：用户看到什么、每天怎么用、每个页面有什么、从 TradingView 等产品继承什么、前端怎么建。
> 定位：一个选股平台。它给出按顺序排列的推荐、每只股票的买卖点与持有计划，并持续公开这些建议的对账结果。它不代替用户下单。

## 1. 主线

```text
盘前  ─ 看“今日”：市场状态、隔夜与日历事件、数据是否新鲜、持仓告警
      ─ 看“推荐榜”与“回避榜”：按周期分榜，每只带解释卡与证据标签
      ─ 看“板块”：强度榜、升温预选池、板块内的角色分组推荐
盘中  ─ 个股工作台：图表、四个面、买卖计划；消息与异动推到持仓和观察池
      ─ 告警：持仓利空、计划失效、封单衰减、板块升温
盘后  ─ 复盘：今天的榜单与昨天的榜单对账、策略联赛、龙虎榜与席位、社区观点对账、笔记
全程  ─ 策略库与联赛：每个策略的规则、证据、前向战绩、状态变化
      ─ 数据健康：每个信息源是否在线、每张表是否新鲜
```

三条贯穿所有页面的规则：

1. **每个结论带证据标签**：已验证、检验中、未检验、已证伪。标签来自策略登记库，不由页面自己决定。
2. **每个数字能追到来源**：点开看到它依据的数据、时刻、快照号。
3. **数据不新鲜就显示不新鲜**：页面角标与全局状态条同源于数据健康。

## 2. 页面

| 页面 | 核心内容 | 对应用户需求 |
|---|---|---|
| 今日 | 市场状态五轴、指数与广度、今日日历、隔夜外盘提示、持仓与观察池告警、推荐榜摘要、数据健康摘要 | 把国内外各类因素放在一屏 |
| 推荐榜 | 短线、波段、长线三榜与回避榜；每只：名次、融合分、投票策略及其证据等级、四面信号摘要、风险标记、入场方式、退出计划；历史榜单与对账 | 按推荐顺序排列的个股 |
| 板块 | 热力图；强度榜与升温榜；升温预选池；板块详情：成分、梯队、角色分组（龙头、中军、跟风、补涨）的推荐、相关消息、板块指标走势 | 每个板块里最值得关注的几只；快速升温板块提前挑出优秀个股 |
| 个股工作台 | 第 3 节 | 技术面全分析、买卖点、持有计划、做 T 与网格 |
| 消息 | 事件线（按事件簇，而不是按单条快讯）、确认等级、来源链、映射到的板块与个股、已反映程度；财经日历 | 实时消息面及其多源校验 |
| 龙虎榜与席位 | 当日榜单；席位画像页（统计、区间、样本数、常同榜席位）；与推荐、持仓的交集高亮 | 不同营业部不同打法 |
| 情绪与社区 | 连板天梯、晋级率、炸板率、涨停溢价、情绪走势；热度榜（相对自身基线）；评论区观点与历史对账 | 情绪面、散户动向、与评论区讨论结合 |
| 筛选器 | 条件筛选、中文问句解析（确定性规则，识别不了的片段原样告知）、保存方案、用任一已登记策略作筛选条件 | 多条件选股 |
| 策略库与联赛 | 按标签浏览全部策略；每个策略的规格、出处、证据、回测与前向战绩、状态历史；联赛分区积分与分层；自定义回测 | 策略池优胜劣汰、分类与路由 |
| 组合 | 融合纸面账户、各策略纸面账户、用户账户；持仓、订单、机会账本（没买到的后来怎样）、实现缺口 | 买卖点的验证 |
| 复盘 | 每日自动生成：市场、板块、梯队、榜单对账、告警对账、联赛变动；用户笔记绑定到股票与时间点 | 盘后复盘 |
| 数据健康 | 每个源的状态、最近成功时刻、产出速率；每张表的新鲜度与质量分；作业运行；缺口与回补 | 信息源中断时是否仍在刷新 |

## 3. 个股工作台

工作台是一个可保存的工作区：布局、指标与参数、画线、笔记、告警、交易计划都存进数据库，换设备、重启后原样恢复。现状这些状态分散在浏览器本地存储与进程内存里（01 卷第 4 节）。

### 3.1 区域

| 区域 | 内容 |
|---|---|
| 主图 | 日、周、月与分钟周期；K 线类型切换；均线、布林带等叠加；涨跌停价线；买卖点与计划价位标注；事件标记（公告、龙虎榜、消息簇）；除权标记；复权方式切换 |
| 副图 | 成交量、MACD、KDJ、RSI、换手、量比等，可增减、可调参 |
| 多周期并排 | 日、周、月同屏，十字线与时间轴联动 |
| 分时与盘口 | 分时、均价线、五档、封单变化、集合竞价与盘后时段 |
| 四面面板 | 消息：相关事件线与确认等级；情绪：热度 z 分数、社区观点摘要与历史对账；资金：龙虎榜席位及其画像、解禁与增减持、两融；技术：指标读数、形态命中、位置。四个面并排，不合成一个数 |
| 相似情景 | 历史上相似局面之后的收益分布（经验分布，不是预测），标明样本数 |
| 交易计划卡 | 第 3.2 节 |
| 笔记与历史 | 用户笔记、这只股票历次上榜与对账、历次告警 |

### 3.2 交易计划卡（买卖点与持有计划）

```text
TradePlan（带版本；每次变更是新版本并写明原因）
  依据            哪些策略把它选出来，各自的证据等级
  入场            方式（次日开盘 / 不追高 / 回踩挂单 / 分批）、价位或条件、失效条件
  仓位            按账户规则给出的股数与金额（整手）
  止损            价位与依据（百分比与波动倍数取紧者；默认值见 05 卷第 9.5 节）
  止盈与退出      规则列表：固定持有期、分批、条件退出；每条带证据等级
  持有计划        预计持有的交易日数、期间的检查点（财报日、解禁日、议息日）
  操作策略        可选的做 T 或网格模板；附“在这只股票上历史回放的结果分布”（含最低佣金）
  风险            席位风险、热度过高、已确认利空、流动性、监管关注
  失效规则        可执行的条件，触发即把计划标为失效并告警
```

- 计划由操作策略生成，用户可以改；用户改过的版本标记为“用户修改”，其结果单独对账。
- **消息驱动的计划变更**：与这只股票相关的事件簇被确认后，计划自动重新评估；若结论改变，生成新版本并在告警里写明“因哪条事件、改了什么”。
- 每份计划从生成起就进入纸面账户按规则执行，到期自动对账。这就是“给出买卖点之后再验证”的闭环。

### 3.3 图表能力

| 能力 | 做法 |
|---|---|
| 指标 | 后端指标库计算，前端渲染；参数面板改参数即时重算并保存到工作区 |
| 画线 | 趋势线、水平线、通道、斐波那契、矩形、标注；对象存库；可在线上挂告警 |
| 回放 | 把数据截到某一天，逐根推进；回放时四面面板与计划卡也只显示当时可知的内容 |
| 对比 | 叠加指数、板块指数、其他股票（归一化） |
| 形态与结构标注 | 形态库命中、分型与中枢、筹码分布（标注为估算） |
| 快照分享 | 导出当前图表与标注为图片 |

图表底座用 lightweight-charts v5（Apache-2.0，需保留署名；多窗格与插件机制可承载副图与画线）。指标、画线、回放、多图联动自研。TradingView 的高级图表库许可条款未能核实，不纳入方案（09 卷）。

## 4. 功能继承：从别的产品学什么

调研对 TradingView、同花顺、东方财富、通达信、开盘啦、韭研公社、雪球、TrendSpider、Finviz、Danelfin 等做了功能拆解（09 卷；国内产品多数只能核到应用商店描述）。结论分四档。“继承”指用公开功能说明与开源组件自行实现，不抓包、不绕过付费。

### 4.1 必须继承

| 功能 | 学谁 | 在本平台的位置 |
|---|---|---|
| 多周期图表、副图、指标参数面板 | TradingView | 工作台 |
| 画线工具（对象存库） | TradingView | 工作台 |
| 条件筛选器、保存方案 | TradingView、Finviz | 筛选器 |
| 板块热力图 | TradingView、Finviz | 板块 |
| 服务端条件告警、多条件组合 | TradingView | 告警 |
| 连板天梯与晋级率、涨停原因、题材库 | 同花顺、开盘啦、韭研公社 | 情绪、板块 |
| 板块强度排行与升温预选 | 开盘啦 | 板块 |
| 龙虎榜与席位画像 | 同花顺、东方财富、开盘啦 | 龙虎榜与席位 |
| 集合竞价异动 | 开盘啦 | 今日、工作台 |
| 筹码分布、分时与五档 | 同花顺、通达信 | 工作台 |
| 公告中心与解读、个股消息流 | 开盘啦、各家 | 消息、工作台 |
| 复盘模板 | 开盘啦 | 复盘 |
| 可解释评分卡 | Danelfin 等 | 推荐榜解释卡（分数由代码算，文字由模型写） |
| 回测报告、策略前向跟踪 | TradingView、TrendSpider | 策略库与联赛 |
| 自选分组、持仓跟踪 | 各家 | 组合、工作台 |

### 4.2 应该继承

在画线上挂告警；多图布局保存与联动；K 线回放（这三项在切换之后交付，08 卷 M6）；自然语言选股（解析成结构化条件，不直接生成结果）；用策略当筛选条件做全市场扫描；自动形态与趋势线识别；参数敏感性扫描；无代码策略搭建（条件积木编译成结构化规则）；区间统计；图表快照；财经日历与异动提醒；命令面板与快捷键；模拟交易；市场宽度；面向外部智能体的接口。

### 4.3 可选

更多 K 线类型；基本面筛选；对外推送钩子；互动平台问答检索；数据导出；兼容外部脚本语言（已知的开源兼容方案是强传染许可，且原生支持仍在试验阶段，只作为导入方言考虑）。

### 4.4 不继承

| 功能 | 理由 |
|---|---|
| 券商接入与自动下单 | 平台定位是选股与计划；合规与资金风险不在范围内 |
| 社区内容生态（发帖、观点广场） | 无法复制，也不是目标；只做外部热度与观点的采样对账，不转载原文 |
| 手写总分、“主力资金”类口径不明的指标作为核心卖点 | 与证据原则冲突 |

### 4.5 海外产品没有、A 股必须有的 15 项

连板天梯与晋级率；涨停原因分类；题材与产业链库；板块强度与升温预选池；龙虎榜与席位画像；集合竞价异动；情绪周期指标；涨跌停价与一字板识别；炸板、回封、封单与封流比；T+1 下的回测与做 T 规则；风险警示、新股、北交所制度过滤；筹码分布；公告与互动平台解读；复盘模板；解禁、减持与监管异动提示。

### 4.6 值得照搬的交互细节

指标参数所见即所得；告警在图表上发起，条件、频率、通知一页完成；回放可调速并多图同步；布局与十字线、时间、画线同步；图表状态可保存并分享；画线对象可挂告警；右键菜单直达常用动作；全局快捷键与代码搜索；数据表可停靠到底部；每条告警有送达状态。

## 5. 告警

| 类型 | 触发 | 默认级别 |
|---|---|---|
| 持仓利空 | 持仓股出现已确认的利空类事件 | 高 |
| 计划失效 | 交易计划的失效规则被触发 | 高 |
| 卖点 | 持仓的退出规则触发 | 高 |
| 宏观或政策冲击映射到持仓行业 | 已确认的行业级事件 | 中 |
| 观察池动态 | 观察池股票的事件、异动、上榜 | 低 |
| 板块升温 | 升温预选池触发 | 低 |
| 数据健康 | 新鲜度目标被突破、源熔断 | 运维 |

每条告警记录：依据的事件、告警时价格已经走了多少、送达状态、到期后的对账结果。推送按（类型、对象、版本）幂等。现状告警只写进日志文件，用户收不到（01 卷 #38）。

## 6. 前端架构

| 方面 | 规格 |
|---|---|
| 技术 | React 19、Vite、TanStack Router 与 Query、轻量状态库；类型与请求客户端由契约生成 |
| 数据流 | 服务端状态全部经 Query；SSE 推送 `{主题, 键, 版本}`，前端按主题让对应查询失效；旧数据留在屏幕上直到新数据到达；请求可中止 |
| 前端不算数 | 分数、排名、涨停判定、收益、指标值全部来自后端；前端只做展示映射 |
| 工作区状态 | 自选与分组、布局、图表状态、画线、笔记、告警规则、交易计划、保存的筛选、复盘条目，全部经接口存入数据库；浏览器本地只缓存不重要的界面偏好 |
| 视图注册 | 一张视图表驱动导航、路由、快捷键、命令面板；加一个页面等于加一行与一个目录 |
| 设计系统 | 沿用现有的设计令牌思路：红涨绿跌；金色只表示高度与空间；交互色与涨跌色不混用；数字等宽；动效统一并尊重“减少动态效果”设置 |
| 证据标签与新鲜度角标 | 设计系统的一等组件，所有页面共用 |
| 图表 | 主图与副图用 lightweight-charts；热力图与统计图用 ECharts；长表格虚拟滚动 |
| 性能预算 | 首屏可交互不超过 2 秒（内网隧道）；5,000 行表格滚动不掉帧；切换股票后主图 300 毫秒内出图 |
| 可达性与键盘 | 全部主要操作可用键盘完成；焦点可见；对比度达标 |

## 7. 面向智能体的能力面

沿用“能力只定义一次”的做法。只读与写入分别标记；会产生写入的读取接口不允许存在。第一版的资源如下，路径统一以 `/api/v1` 开头；请求与响应的模型在 `contracts/api/`，由 M0 的契约卡逐个定稿。

| 资源 | 读取 | 写入 |
|---|---|---|
| 市场状态与今日摘要 | `GET /market/state`、`GET /market/today` | — |
| 推荐榜与回避榜 | `GET /picks?date=&board=`、`GET /picks/{date}/{board}/versions`、`GET /picks/track-record` | — |
| 板块 | `GET /sectors`、`GET /sectors/{id}`、`GET /sectors/{id}/picks`、`GET /sectors/heat-pool` | — |
| 个股 | `GET /instruments/{id}`（概要与标签）、`/bars?period=&adjust=`、`/indicators`、`/signals`、`/events`、`/seats`、`/analogs` | — |
| 交易计划 | `GET /plans?instrument=`、`GET /plans/{id}/versions` | `POST /plans`（生成或用户修改，产生新版本） |
| 操作策略回放 | — | `POST /tactics/replay`（在指定股票与区间上回放某个操作策略） |
| 消息 | `GET /intel/clusters`、`GET /intel/clusters/{id}`、`GET /calendar` | — |
| 龙虎榜与席位 | `GET /lhb?date=`、`GET /seats/{id}` | — |
| 情绪与社区 | `GET /sentiment/ladder`、`GET /sentiment/heat`、`GET /sentiment/opinions` | — |
| 筛选 | `POST /screen/parse`（问句解析，无副作用） | `POST /screen/run`、`PUT /workspace/screens/{id}` |
| 策略与联赛 | `GET /strategies?tags=`、`GET /strategies/{id}/{version}`、`GET /league/{season}` | `POST /strategies`（登记）、`POST /backtests`（入队） |
| 组合 | `GET /accounts`、`GET /accounts/{id}/positions`、`/orders`、`/opportunities`、`/performance` | `POST /accounts/{id}/fills`（回填真实成交） |
| 告警 | `GET /alerts` | `PUT /workspace/alert-rules/{id}` |
| 工作区 | `GET /workspace/{kind}`，`kind` 取 watchlists、layouts、chart-states、drawings、notes、reviews 之一 | 同路径的 `PUT`、`DELETE` |
| 数据健康 | `GET /health`、`GET /health/sources`、`GET /health/datasets`、`GET /health/jobs` | `POST /ops/jobs/{id}/run`（需鉴权） |
| 实时推送 | `GET /stream`（SSE） | — |

SSE 的每条消息是 `{topic, key, version, event_time}`，主题见 03 卷第 6.2 节。它只通知“什么变了”，不携带业务数据；前端据此让对应的查询失效并重取。

## 8. 合规边界

- 页面固定位置显示：平台输出的是基于规则与统计的研究结果，不构成投资建议；每条结论的证据等级如实标注。
- 外部内容只存标题、链接与结构化抽取结果，不转载全文。
- 不绕过任何站点的登录、验证码与访问限制；源不可用就在数据健康页显示不可用。
