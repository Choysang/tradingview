## 3. 需要修订的发现

### CR-A01：高，基线失效仍缺具体发布行为

位置：综合文档第6节；RP030、RP064。

候选失效时baseline回到1.00只解决“候选无效、基线有效”。当PC桥分过期、基线所需关键字段缺失或基线计算失败时，基线本身无法承担1.00。RP030验收承诺“主干失效均有确定输出”，正文尚未给出这最后一种。

建议写为可直接实施的二选一政策，并默认选定其中一种：

1. 若有已经批准且可由服务器独立运行的备用排序基线，按版本化路由切到该基线。
2. 否则本stage失败，不产生新READY release；旧已发布包仅作历史/陈旧查看，当前actionability评估以缺失输入阻止新可执行计划。写明确原因baseline_unavailable，恢复后生成新版本。

禁止默默沿用过期桥分，或把尚未获准候选放大到满额。这里不要求额外用户确认，只需确定实现语义。验收覆盖PC离线、过期分数、一个10%候选、基线关键源失效及恢复。

### CR-A02：高，RP018段落含21项能力，现理由未形成逐子能力决议

位置：RP018；R02-073与R02-075。

原文两个段落列15项“应该继承”、6项“可选”。现reason以研究笔记、日历、组合分析和策略助手作总括，其中研究笔记并非这两段的核心列项。每项的实施依赖和价值并不相同；用一个段落ID覆盖会掩盖以下能力：

- 画线告警、多图布局联动、K线回放；
- 自然语言条件解析、策略全市场扫描、自动形态与趋势线；
- 参数敏感性、无代码条件积木、区间统计；
- 图表快照、财经日历/异动、命令面板/快捷键；
- 模拟交易、市场宽度、外部智能体能力；
- 更多K线类型、基本面筛选、外部推送hook、互动平台问答、数据导出、外部脚本方言。

建议在正在生成的产品能力表内各给稳定子ID，写采用/研究/延期/不采用、理由、数据合同、接口绑定、owner和退出条件，并让RP018显式链接这些子ID。不是要求本轮实现21项功能，而是给完整重写规格一个不遗漏的可执行去留表。

### CR-A03：中，论文壳与内部台账需要精确的跨记录链接

位置：RP043、RP082—RP136。

RP043覆盖21条内部结论，却只笼统指向01/06/07；每条需能查到具体decision_id或实验记录。否则E072/084/083、E088或E090这样的不同问题会被同一“旧结果待复现”口径淹没。建议增加unit_id→audit/strategy/ledger decision IDs→source experiment ID的映射。

55条文献壳的reason/action/acceptance完全相同可以作为索引层，但最终必须一条链接一个paper/claim ID及明确采用/修正/不采用的理由，不能只绑定整个reference_papers_v32.json。最终验证应检查所有引用存在、每条至少一项不同的具体方法/限制，并对未核身份或未读全文作相应降级。本冷审不重新声称读完55篇原论文。

### CR-A04：中，root.json证据类型与支持链不一致

机器检查显示191条evidence.kind全部为input，而分工规定的类型是repo、primary_source、reasoning或internal。原文定位有必要，但只能支持“原文这样说”，不能独立支持费率、版本、文献结论等裁决事实。

建议统一kind=internal并用role=input_record区分原文；对已核外部事实补primary_source或明确定位至来源登记的record/claim；对数学修正引用具体算式/反例；对仓库判断引用固定commit与文件。这样最终验证器既能处理类型，又能追踪实际证据。

这不是要删掉输入原文来源，而是让“审查对象”与“支持本次结论的来源”分工清晰。

### CR-A05：中，产品API扩展卡需要可验收的数据与命令语义

位置：综合文档第12/13节；RP013、RP021、RP023、RP034。

保留31现有操作且明确扩展是正确决定。最终映射表不应只有“此能力需要新API”的标题，应至少使下表能力能独立开工：

| 能力 | 能复用什么 | 必须明确的剩余合同 |
|---|---|---|
| 用户计划编辑/生成 | TradePlan、decision.trade_plan、现有getTradePlan | 写命令、expected plan/account/release版本、幂等、用户修改来源、新版本/失效语义 |
| 操作策略回放 | createExperiment、EvaluationContext、唯一账本 | 指定股票/区间/策略/账户初始状态/执行能力，异步结果、未知数据/不可成交原因 |
| 自然语言筛选 | 条件AST和统一feature层 | 解析失败的原文片段、字段单位、run输入快照、候选母集、分页稳定性 |
| 保存筛选/工作区删除 | layout/watchlist/annotation写入口可部分复用 | 每种对象CRUD、owner、乐观并发、条件版本；不能以annotations裸文本代替所有资源 |
| 告警与画线告警 | outbox、UpdateNotification、annotation | rule/trigger/delivery attempt分别持久化、TTL、去重、停用生效点、目标渠道 |
| 全市场事件/日历/席位页 | 个股evidence/community/seats读模型 | 全局scope与实体查询、报告窗口、游标、覆盖、版本和权限 |
| 账户成交回填 | execution account_event/journal | 实际回报source ID、更正链、对账挂起/恢复；不是直接调模拟买卖 |
| 作业人工触发 | ops.job_definition/run、command_receipt | 权限、版本、参数合同、幂等、运行回执和取消/重试语义 |
| 榜单历史/机会账本/复盘 | Ranking、Release、Evaluation | 版本查询范围、未成交分母、原决策与后验评价分开、时间序列导出 |

最终每卡至少含proposed operation_id、request/response schema ref、授权scope、读写table/dataset、应用服务、版本/幂等、事件、验收、实施状态。新增卡不计入现有31，直到公共合同和绑定真正生成。无需为可复用能力另造同义API。

### CR-A06：中，跨资产单位需限定A股规范域

位置：综合文档第4节“金额统一元，数量统一股”。

用户需要外盘、期货、FX、商品作影响因素，这些数据不能统一成CNY元/股。建议改成“A股股票金额以CNY元、成交数量以股；其他资产保留明确currency、unit、contract_multiplier、venue/session，跨资产比较在派生特征中显式转换”。现有market.bar_projection限定CNY，因此cross-asset引用应走通用观测/独立数据集，不能把非CNY写进该热表。

### CR-A07：中，RP024未明确处置固定免责声明条款

位置：RP024覆盖R02-132/133/134。

R02-132是“固定位置显示研究用途/不构成投资建议”，现reason/action/acceptance讨论的主要是正文留存与访问限制，没有判定这个具体条款。建议明确保留简短研究用途与证据说明，还是转为关于页/帮助页说明；无需增加弹窗、审批或重复警告。选择与用户要求不过度防护一致即可，但应有明确去留理由。

### CR-A08：低，五职责命名需给旧卷到新配置的映射

上传五职责是collector/stream/worker/api/watchdog；综合文档第3节写API/摄取/分析/研究/发布。二者可以不同，但“研究”在PC、“watchdog”在运维，读者需知道原职责没有消失。

建议加一行映射：collector→摄取；stream→分析快任务；worker→分析批任务/发布；api→产品API；watchdog→外部服务管理与健康监督；research为可离线计算配置。并明确不会强制六个或更多常驻Python进程。

1. 重新校验475单元一对一覆盖，以及子能力、具体实验和paper claim的链接存在性；保留当前零漏零重复结果。

4. 合并后的正文、API映射、数据集作业表、合同计数必须使用一致状态：规格/已生成合同/参考实现/生产已验证分开。
