# 主控开发Agent启动任务

你要从零实现一个面向沪深主板A股的交易研究网站。目标是在国内外消息、技术面、市场情绪、产业关系与公司数据变化时，持续给出排序清晰的个股候选、多周期分析、条件化买卖和持有计划，并通过统一回测、前向模拟和策略发现持续改进。

## 必须读取的输入

完整读取`spec/GREENFIELD_SPEC.md`、`spec/IMPLEMENTATION_GUIDE.md`、`contracts/README.md`与Schema/fixture、`catalogs/README.md`与三个JSON目录。以这些内容为起点建立新目录与新仓库骨架。

业务实现Agent不得导入、复制或据旧项目业务函数进行翻译式重写。只有迁移Agent可以读取旧数据、序列化格式、冻结实验说明与相关导出代码，以生成一次性转换器。旧代码审计用于理解已经发现的问题；新设计的契约与行为是实施依据。

## 首个可运行成果

建立版本化契约、PostgreSQL迁移、最小来源适配器、日线与分钟样本、两个确定性策略和一个模型策略。把一个新事件接到影响分析、候选排序、TradePlan、页面、模拟订单与Fill、账户账本和研究归因。先运行明确标记的fixture，再连接一个真实已具备权限的来源与行情。

核心对象为Observation、EvidenceEvent、ImpactAssessment、FeatureSnapshot、DecisionSnapshot、TradePlan、OrderIntent、Fill、LedgerEntry、StrategySpec、ExperimentRun、ModelRun与DatasetManifest。JSON Schema是契约种子；新增完整字段需要遵循规格、更新样例并由契约负责人合入。

## 并行工作方式

按实施指南分配A至J十个逻辑角色：契约与集成、数据、行情与特征、消息智能、执行、决策、前端、研究、迁移、独立验收。逻辑角色不要求同时启动十个Agent；按照实际并发数分波次执行。在独立worktree工作，每个任务声明独占路径、依赖、输入样例、验收和交付物。

公共Schema及集成分支只有一个负责人。涉及接口变更先提交差异和消费者更新方案；其他Agent使用冻结样例推进。合并时校验真实行为和对应场景，不以页面完成或函数名对齐替代集成验收。

## 不可省略的运行语义

1. 保存原文与修订，分别记录源发布时间、系统首次收到时间、分析完成可用时间和决策时间。历史回放只能使用当时已可用的版本。
2. 推荐、详情、回测和前向流程引用同一决策与计划。固定N日信号收益和计划真实执行收益分别命名。
3. 模型可以提出入场、退出、持有、仓位和策略改变；PlanCompiler将结构化提案转换为有效版本。模型调用不阻塞行情规则处理。
4. 使用typed AST、明确的信号时钟、触发去重和holding anchor。模型在运行中产生的新判断必须追加为新版本。
5. 计划替换不能删除旧委托与晚到成交。账户变更使用短事务、稳定幂等键和版本校验；等待外部确认期间不保持长事务。
6. A股规则按证券与生效日期选择，包含T+1、可卖库存、涨跌停、停牌、交易时段、数量、费用和公司行动。15:00快照与15:30最终全日量额区分。
7. 研究快筛可并行运行；晋级均使用统一执行内核。完整保存试验次数、失败结果、暂停与复活条件。
8. 来源未连接、字段未知、模型失败和成功中性结果使用不同状态。不得用合成行情或估算字段伪装真实采集。

## 自动推进与交付

研究、采集、提案、计划重算和模拟运行按已配置政策自动推进。默认paper模式，真实券商接入属于后续独立集成。遇到某来源缺权限时登记缺口，继续完成已具备条件的闭环；无需因此停止其他模块。

按M0至M5交付。每次提交说明完成的行为、接口变化、验证证据和剩余缺口。先完成第16章纵向样例，再逐步满足第14章V01至V22。性能数值是待实测目标，策略效果是待积累的实验结果；报告必须区分目标、实现与实测。

最终交付应能从网页上的一条推荐追溯到原始证据、因子、策略与模型版本、具体计划、委托和成交，再追溯到评估结论，并允许新增一个来源、策略或模型而不重写这条主链。


## v2必读扩展

先读spec/V2_SYSTEM_DESIGN.md、spec/CODE_AUDIT_V2.md、spec/PLATFORM_SYNTHESIS.md、spec/PAPERS_SYNTHESIS.md和contracts/V2_PROTOCOLS.md，再按GREENFIELD_SPEC实施。首发加入NATS JetStream和DuckLake共享快照；单进程原型与分布式实现分开验收。

同时满足V2-01至V2-27。选股、配置、入场、持仓操作、执行、退出分别输出有类型提案；同账户只有一个物理目标和账本。多个策略不各自直接消耗同一现金/库存，不把论文入库当策略晋级，不把模型票数当独立证据。用traceability/记录每个新增业务组件的需求、证据、决策与验证。
