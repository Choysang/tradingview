# Pulse A股交易平台重写实施包 v2

版本2.0，证据与代码检查截止2026年11月10日。审计基线：`6f5c57f8df73c58f0340dab6977b95c05d21740c`。

本包将国内外消息、推荐排序、多周期个股分析、持仓操作和策略研究收束到同一套共享数据、版本契约、账户与评估口径。建议独立新建项目；新业务代码从本规格和可观察行为重新实现，旧仓库只提供迁移数据、历史实验与反例，不作为必须继承的实现模板。

## 1 阅读顺序与权威边界

1. `spec/V2_SYSTEM_DESIGN.md`：本轮深化的共享数据、多策略账户、论文证据、平台继承和27个新增验收场景。
2. `spec/GREENFIELD_SPEC.md`：完整产品与领域规格，保留16章和22个基础验收场景。共享基础设施选型已同步为v2，不保留两套首发方案。
3. `contracts/README.md`、`contracts/definitions.schema.json`、`contracts/V2_PROTOCOLS.md`：37项定义的机器可校验种子，以及尚待实现的扩展协议。种子没有覆盖所有v2对象；协议表不是已经生成通过的完整Schema。
4. `reference_models/README.md`：共享特征和账户的可运行语义，45项已通过测试及明确实现边界。
5. `spec/PLATFORM_SYNTHESIS.md`、`spec/PAPERS_SYNTHESIS.md`及`research/`：10个平台、56项能力、38篇论文的证据、设计推断、适配与复现步骤。
6. `traceability/`：旧代码清点、审阅深度、设计理由与需求映射；不把自动清点冒充逐行语义审计。
7. `spec/IMPLEMENTATION_GUIDE.md`及`AGENT_START_PROMPT.md`：多Agent的文件所有权、契约交接、开发波次与验收入口。
8. `spec/CODE_AUDIT.md`、`spec/CODE_AUDIT_V2.md`及`patches/`：30项审计发现、原有3项局部修复、补丁边界和迁移依据。

`Pulse_Ashare_Rewrite_Full.md`与Word主体保持一致，合并九个部分。完整方法卡、数据目录、具体代码理由、查询日志和参考代码放在本包，正文按路径引用。`V2_SUMMARY.json`给出机器可读数量；`PACKAGE_MANIFEST.json`记录文件摘要与交付状态。

## 3 统一架构的几个固定约定

采用模块化单仓及独立worker：React/TypeScript/Vite、FastAPI/Pydantic、PostgreSQL、NATS JetStream、DuckLake/Parquet、DuckDB/Polars与Temporal。固定具体依赖版本前执行兼容矩阵验证，不按想象的未来版本号生成依赖。

- PostgreSQL保存账户、计划和业务事务；outbox/inbox连接持久事件。JetStream消费者各自记录进度，慢策略不阻塞采集；只服务UI的最新值流可以合并，但业务事件不可按UI逻辑丢弃。
- DuckLake共享分析快照；先提交数据，再将READY manifest与outbox纳入业务事务，通过协调器处理跨库中断，不宣称两者天然原子。
- 历史查询同时固定`snapshot_id + decision_as_of + availability_policy`。版本一致不自动证明当时可见；公司行动、新闻修订、解析和模型完成时间必须纳入可得性。
- FeatureDAG按需求求依赖闭包。缓存键包含数据、实现、依赖、政策、日历、复权和决策时点；健康并发合并执行，故障允许重算，但只有持有提交权的结果可以发布。
- 策略按选股、配置、入场、持仓操作、执行、退出六种角色组合。多种思想可以同时使用；同一物理账户的现金、库存和未成交订单始终由唯一账本协调。
- SessionCoordinator合成分析提案，PortfolioCoordinator合成账户目标，PlanCompiler生成正式计划；实际订单触发时由ExecutionCoordinator再次检查并原子预留。未来条件计划生效不等于已经占用资金。
- 做T/网格按同起点的总净值增量评价，同时计入未闭合腿、剩余库存、费用和买不回的机会成本；不能用显示成本下降或已实现价差代替收益。
- 模型通过稳定工具与能力接口接入，保存具体ModelRun；不绑定未核实的未来型号。公共字段、策略生命周期与TradePlan状态以契约中的唯一命名为准。

## 4 证据如何进入开发

每项外部材料拆成“来源事实—本站推断—研究假设—实现—验收”五种记录。论文的发表状态、读到的范围、数据市场、成本假设和作者结果分开保存。`research/papers_registry.json`使用规范状态码和原文状态说明；38项`hypotheses.json`均为`specified_not_implemented`，盈利验证均为false。

多方校验先判断是否独立来源。转载同一公告不增加独立证据数；摘要、正式PDF和代码出现差异时保留冲突，不静默挑选更好的结果。没有可核实证据的数据接口、未读全文和尚未召开会议都明确登记状态。

新代码每个业务组件与重要边界应关联requirement、ReasonRecord、输入输出契约、不变量及行为验收。理由台账不是给每行生成一句泛化注释；它需要能回答“删除会失去什么能力”“替代方案为什么未采用”“哪个反例能证明这段逻辑必要”。数据、论文、模型和策略更新产生新版本，不改写过去的决策与试验结果。

## 5 运行本包的有限验证

共享特征及账户参考实现仅需Python标准库：

```bash
python -B -m unittest discover -s reference_models -p 'test_*.py' -v
```

契约种子需要`contracts/requirements-validation.txt`中的依赖：

```bash
python contracts/validate_fixture.py
```

第二项验证包含结构、选定引用、时点/单位关系及8个拒绝反例，不等于49个设计场景已全部实现通过。`traceability/ledger_negative_input_repro.py`是针对旧基线C27的复现，需要相应旧仓库路径，不能当作新实现运行入口。

包内目录、论文状态、数量、来源引用闭合及参考测试方法数量可用`python validate_package.py`复核；它只检查这些结构关系，不执行训练、收益回测或完整网站。

## 6 开发启动顺序

先交付一条真实来源事件进入系统、产生证据、共享特征、推荐与个股计划、模拟成交、净值归因和研究记录的纵向闭环。随后扩展来源覆盖、平台能力和研究候选。开发Agent可以并行写数据、界面、策略、账户与研究模块，但公共契约和文件所有权唯一，跨模块使用同一fixture和行为场景验收。

实时消息可以自动更新事实、状态与计划；新的策略定义、模型政策和参数经过版本化实验再晋级。研究发现、正式接入、样本外验证和前向验证分别计量，避免“发现一篇论文”被误记成“上线一项有效策略”。
