## 已复现并修复的问题

### IA01：独立 Decimal Context 仍会继承全局默认 trap

初始改法使用 `Context(prec=50, rounding=ROUND_HALF_EVEN)`。虽然不再直接继承调用线程的 `getcontext()`，未指定字段仍来自 `decimal.DefaultContext`。

实测把 `DefaultContext.traps[Inexact]` 设为 True 后，对同一合成数据 `10 / 3` 计算 VWAP 抛出 Inexact；增加 Rounded trap 同样影响结果。这与固定数值政策不符，也可能受同进程其他库的初始化影响。

修复：作者新增完整显式 Context 工厂，固定精度、舍入、Emin/Emax、capitals、clamp、flags、traps。独立测试同时改变全局默认 trap/指数范围和局部调用精度/指数范围，结果仍符合手算值；微秒年龄也不受影响。

### IA02：正值 VWAP 量化下溢为 valid 的零价

输入成交额 `0.000000000001` 元、成交股数 `10000000000000`（整数且在 JSON 安全整数范围内），两个输入均符合本参考 numeric(38,12) 约束。正商被量化成 `0E-12`，返回 `quality_status=valid`、`field_status=derived`。

这是数值边界错误：固定精度允许舍入，不应把不能表达的正价格包装成有效零价。原函数只有“输入成交量为零”的判断，未覆盖“计算后被量化为零”。

修复：作者对正商量化为零明确抛出 `NUMERIC_RESOLUTION_UNDERFLOW`。同一政策也适用于极小正换手率，不暗中输出一个真实零值。独立反例已通过。

### IA03：完全过时的修订冲突阻塞最新无歧义状态

初始选择逻辑遇到任意自然键的同最高修订多记录便立即返回 `AMBIGUOUS_REVISION`。合成输入包含 09:30 的冲突旧记录两条和 09:31 的唯一有效新报价，09:31 查询仍返回 disputed，没有使用无歧义新状态。

修复：先登记所有可得最高修订中的冲突组，再经过时点和有效期筛选，只有冲突组影响当前候选时阻止选择。不能通过过滤“治好”真正的修订冲突：独立测试另外构造同一最高修订一条在目标前、一条在目标后的冲突；虽然时间过滤仅剩一条，只要该组影响选择，仍返回 disputed。

## 冷读推动的时点定义修正

### IA04：exact_event 与 state_hold 使用不同排序时钟

冷读时二者统一按 `effective_from or event_time` 选择最新记录。对于 exact_event，两条记录的业务生效顺序与事件时刻顺序不同，可以选中错误记录后报告 EXACT_EVENT_REQUIRED，漏掉本来存在的目标事件。

作者在独立复现脚本完成前已修复为：state_hold 按业务生效时刻，exact_event 按事件时刻。独立测试使用 09:30 事件/09:30 生效与 09:31 事件/08:00 生效，09:31 exact_event 正确选择第二条。这里记为冷读发现与最终回归验证，不声称保存了修改前的运行反例。

### IA05：换手率分母在窗口内变更

初稿对整段成交股数使用窗口结束时有效股本。这个算法必须声明口径，不能暗示已完成区间内股本变化的分段处理。作者选择的有限参考政策是：若选中的股本在成交窗口内才生效，返回 missing / `DENOMINATOR_CHANGED_WITHIN_WINDOW`，要求更细窗口；此参考不进行分段积分。

独立测试给出 09:30—09:31 成交区间与 09:30:30 股本变动，结果明确缺失，不产生伪装成已解决变更的换手率。窗口结束时取分母是明文参考政策，不宣称适用于所有供应商的换手率定义。

## 其余独立验证覆盖

- 修订先于事件时间过滤：最高可得修订把事件时刻改到目标之后，旧修订不会重新出现。
- 晚到修订仅影响较晚 decision_as_of；早先结果保持当时可得版本。
- 最新 invalid 撤回可得后不会退回旧好值；未可得前不会提前使用撤回。
- 同字段的其他来源、映射、方法、会话、交易日、快照中的更高 revision 不会抢占目标 scope。
- 相同数值来自不同 snapshot，不能合成同一个 VWAP。
- 有效区间右端点为排除边界；最新状态到期不会让旧 open-ended 状态重新出现。
- 已公布但尚未生效的未来股本不会提前使用。
- 派生结果 available_at 不早于计算完成，保留原 decision_as_of 和全部输入 snapshot 引用。
- 晚到股本披露可在较晚计算中使用，但不会伪造为早先已知，也不会回填派生可得时间。
- numeric(38,12) 最大正金额在非常小的调用方精度下仍按固定政策计算。
