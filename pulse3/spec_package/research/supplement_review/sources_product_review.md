# 附件来源、产品与工作流建议审查

审查日：2026-11-11。对象为用户新附件及已交付 v3 包；现有包保持只读。本稿供 v3.1 兼容增补集成。下面的“加入”指进入设计与待实现候选，不表示已接通数据、验证收益或部署功能。正式版本继续使用现有 80 张表、31 个 API 操作和唯一账本。

## 一、总体判断

附件有价值的部分，是把平台的盘前、盘中、午间、盘后使用过程写得更具体，特别是评论区观点检验、板块角色、事件图层及跨市场观察。消息—情绪—资金—技术、两阶段选股/个股、席位研究、板块升温池、工作台持久化、统一内核、策略分类和开发 Agent 协作，v3 已有完整设计，不能再新增一套平行模块。

真正值得增补的是：将四时段复盘变成可评分观点记录；将图层显示绑定真实数据能力；将 ETF 二级市场交易与一级市场申赎分栏；为可转债—正股关系建立研究合同；细化竞价和席位研究的可观察边界。保留用户想观察这些现象的目标，替换附件对身份、胜率和领先时间的未证明断言。

附件旧仓库诊断不能当成新证据。实际剧本路径是 `backend/app/playbooks/picks.py`；旧 `docs/research/ledger/README.md` 已有 E091/E092。主审已解析同一基线 `experiments.jsonl` 得到 92 条无坏行记录，README 中有 92 个不同 E 编号。E048/E049/E051 已涉及拉萨、席位预测与组合接入，因此“席位模块完全缺失”“只有 E001–E061”不准确。E051 的旧记录还说明，席位标记与当时主书买入几乎不重叠，添加过滤器没有改变该主书收益。这支持按策略和候选母集验证边际价值，不能全站硬编码一票否决。以上只是本轮读取的旧报告，未重跑其历史数据，不能继承其收益为新版已证成绩。

## 三、真正的增量应如何接入现有合同

### SP04：会话观点卡与到期复盘

原始帖仍进 `intelligence.community_observation`；观点用 `intelligence.claim_revision.assertion_type='forecast'` 和 `object_payload` 承载。该 `object_payload` 不是任意 JSON：生产使用前必须登记新的 `claim_schema_version`，对目标证券、预测期限、目标定义、原始证据版本、概率是否存在和失效条件做强校验。若自然语言只说“值得观察”且没有可证伪目标，应保留为 `opinion`，不能伪造概率以便评分。

API 原观点由 `getStockEvidence → data.claims[].object_payload` 提供；社区采样由 `getStockCommunity → data.observations[]` 提供。到期结果作为新的不可变、已登记结构的结果 artifact，经 `market.feature_result.result_uri/result_hash` 和 `getStockWorkspace → data.features[].artifact` 引用；不回写覆盖预测输入。未来如果要在主张 API 直接嵌入评价结果，需要正式升级响应 schema；本次不偷加字段。

评分分三项：事实主张是否被证据支持；有明确概率的预测是否校准；把它用于某一选股/持有策略后是否产生成本后边际价值。第三项才接 `research.hypothesis`、实际策略 `strategy.instance` 和 `research.experiment_run`。后者 `instance_id` 非空，不能为了普通评论评分伪造一个策略实例。普通观点评分可先用特征 artifact 保存。

### SP13/SP14：图层能力矩阵

界面每个图层先声明所需输入：完整逐笔、定时快照、分钟 OHLCV、历史帖快照、席位披露或仅模拟数据。能力来源由 `core.source_endpoint` 精确端点和已登记的内部政策决定；`market.dataset_manifest.coverage_document` 记录实际覆盖，`FeatureResult` 的带合同 artifact 承载图层计算结果/缺失理由。

现有 `SourceHealth` schema 没有 `capabilities` 字段，不能往 `getDataStatus` 塞一个未声明字段。本次可作为服务内部配置和图层结果合同设计；将来若希望一个 API 列出全部能力，应正式新增或升级 DTO。行情缺失时显示“该图层缺少逐笔记录”，不伪造一条完整队列；回放缺少历史社区互动快照时禁用该层，而不是带入今天的点赞数。

### SP15：ETF 观察分栏

已有 `intelligence.funding_observation` 完全足够存储精确定义的不同资金观测：`metric_namespace`、`metric_name`、`methodology_id/version`、`measurement_class`、`trade_or_order_basis`、`observation_window_start/end`、`canonical_value/unit`、`available_at` 和 `field_quality`。前端使用现有 `getStockFundFlow → data.observations[]`，不要创建一个含义不明的 `etf_net_inflow` 总字段。

“成交额放大”可作研究推导，份额变化应注明披露窗口，PCF 额度应标为额度而非执行量。真正实际净申赎需对应源数据合同；没有可靠数据就是缺失。ETF脉冲关联到个股时必须使用当时已知的成分、权重和关联逻辑；重叠 ETF 的同一股票暴露不能按多个独立证据计票。

### SP17：可转债与正股关系

`core.instrument.instrument_type` 可区分产品，但 v3 没有一张专用债股关系表；不能假称已存在。v3.1 选定兼容路径为 `intelligence.claim_revision`：`subject_kind='instrument'`、`subject_key` 为债券稳定 ID、`predicate='convertible_underlying_of'`，以新的严格 `claim_schema_version` 校验 `object_payload` 内的正股 ID 与有效区间；证据沿用 `intelligence.claim_evidence`。原始条款先保存 `ingest.raw_object`。Repository 负责核验两端真实存在和有效期；JSON 内的 ID 不会自动获得 SQL 外键约束。若另作规范观测，也必须经 `core.contract_version` 登记合同，不能未经规划同时维护两份关系真相。

特征结果使用 `market.feature_result` 与完整有序 `FeatureKey.instrument_ids`，`getStockWorkspace → data.features[].artifact` 可引用结果。债券行情不能直接冒充 `CanonicalQuote.volume_shares`；需先登记债券单位的独立源数据合同和结果 Schema。若将来要支持债券下单、账户持仓和高频关系查询，应另开正式 schema/规则扩展，本次没有声称现有股票执行内核已支持。

## 四、值得加入的验收条件

1. 官方单一首发可保持 official_disclosure；经过 180 秒不会自动变成 rumor。
2. 三家转载同一原稿仍只贡献一个 origin_group。
3. 正常没有新稿时传输仍 healthy，内容更新时间不伪刷新；鉴权/429 与业务静默有不同恢复路径。
4. 原观点在盘前冻结；盘后帖子编辑、晚间龙虎榜、日终ETF份额都不会回填当时判断。
5. 对没有预测期限、目标或概率的评论，不生成虚假的预测评分。
6. “观点事实正确”和“采用后收益更好”可出现不同结果，两个结果独立展示。
7. 只持有竞价快照时虚拟未匹配量可显示，逐笔撤单率为缺失。
8. 没有历史 L2 或历史互动快照时回放该图层显示缺口，不以当前数据补全。
9. “机构专用”没有稳定可核验实体时用 report_local_label；不能跨报告当作同一个人。
10. 买五拉萨占比只描述该报告买入榜范围；未上榜不等于没买。
11. ETF 分钟成交额变为 5 倍，不自动生成净申赎或国家队身份。
12. ETF PCF 当日净申购上限不映射为当日实际净申购。
13. 债股关系和转股价只在实际可得且有效区间使用；后续下修不修改旧特征。
14. 可转债停牌、赎回、报价滞后和相对正股不同会话，均不得当作领先证据。
15. 观察池出现 20cm 弹性先锋可以影响板块研究，但不会绕过默认主板推荐母集。
16. 不足十个合格候选时返回真实数量；不把缺失数据补零再凑满榜单。
17. 同一事件重复转载只触发合并更新；具有实质修订时才产生新证据/输入版本。
18. 旧模型结果完成较晚时保留历史解释，不能覆盖更新的 AnalysisRelease。

这些是新增验收定义，并非已在生产执行的测试结果。
