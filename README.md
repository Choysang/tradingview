# Pulse · 用"做实验"的方式炒 A 股

> 一个只做沪深主板的 A 股研究工作台。它每天收盘后自动选股、给出买卖计划；盘中录行情、抓新闻、盯持仓。
> 它和大多数炒股工具最大的不同是：**每一条"战法"都要先写下检验标准，再用当时能拿到的数据回测，最后在真实的后续行情里接受检验。**
> 不管成功还是失败，都记进公开的[研究账本](docs/research/ledger/README.md)，目前已有 80 多条实验。

**本项目只用于研究和学习，不构成任何投资建议。** 历史回测不代表未来收益。

---

## 为什么值得一看

网上的"必涨战法"很多，真正检验过的很少。Pulse 把常见说法逐条放进同一套严格的回测里，下面是一些实测结论：

| 常见说法 | Pulse 的检验结果 |
|---|---|
| 打板、接力龙头能赚钱 | 扣除"小盘、高波动"的风格因素后，打板接力类仍然**跑输**同类股票 1.5–3.7 个百分点（E062） |
| 超跌就会反弹 | 单靠超跌买入不显著；**有利空公告的超跌股之后更差**（E070） |
| 涨得最猛的继续涨 | 近 5 日相对行业涨幅最高的 10%，之后 5–10 日**稳定跑输**同类股票（E070） |
| 美股大跌后，A 股第二天反弹 | 在 2010–2023 年 213 次事件里**不成立**；A 股的下跌在开盘集合竞价时就已经消化掉了（E084） |
| 美联储议息那天别急着买 | **成立**。2010–2023 年 112 次议息，反应日开盘买入当天平均比平常差 0.26 个百分点（p = 0.006，E083） |
| 选股分数排第一的最好 | 分数真正的用处是**避开最差的 20%**，而不是挑出最好的那几只（E071、E079） |

每个结论都有对应的预注册文档、代码和数据口径，见 [`docs/research/`](docs/research/)。

## 新版 Pulse 3（重建中，与旧版并行）

[`pulse3/`](pulse3/) 是按一份完整重建方案从零重写的新版本，**不引用旧代码**，旧版照常运行、所有功能保留。

- 一份契约管全部：每个接口的输入输出都由同一份 JSON Schema 定义，前端类型由它生成。
- 每天收盘后生成一个"分析发布"：选股排名、板块、候选池、交易计划一起发布，要么全部就绪，要么一个都不对外。
- 只有一本账：模拟成交、持仓、费用都走同一个账本，费用按真实账户口径（佣金万五最低 5 元、卖出印花税万五、过户费十万分之一）。
- 数据按"当时能拿到什么"回放：每条数据都记录可用时间，回测不会用到当时还没出来的数据。
- 战法有生命周期：发现、检验、试运行、启用，每一步都要证据；检验失败的标为"已证伪"并保留记录。
- 旧版的好功能（行情看板、筛选、战法库、预警、日历等）以扩展卡片的方式逐项迁入新版。

新版在服务器上与旧版同时运行，经过一段时间的并行对账后再决定是否切换。说明见 [`pulse3/README.md`](pulse3/README.md)。

## 它每天在做什么

**盘后**（交易日 15:35 起，自动运行）
- 同步全市场日线，重新计算融合选股分数。
- **冻结主书**：规则在 2026-11-01 冻结，之后不再调参。持有 5 天，20 个仓位，每天从分数前 40 名里新买 4 只；账本净值走弱时自动少买。每只按 5 万元计，总计 100 万。
- 几个影子账本与冻结主书并行记录：持有 10 天的版本、"剔除最差 20%"的低换手篮子、20 日急跌后的反弹信号。
- 前向监控：统计冻结分数在真实后续行情里的排序能力（IC）和超额收益。
- 市场状态日志：宽基 ETF 是否放量、尾盘成交占比、上涨家数占比、股指期货基差，每天记一行。只记录，不改变买卖规则。
- 联网大模型判断（试运行中，还没有真正调用）：收盘后让大模型联网查融合分数前 30 名和 10 只随机对照的新闻，判断 5 天后能否跑赢主板平均。系统连续 5 个交易日稳定后才开始，攒满 20 个决策日自动停下来对账。只记录，不改变买卖规则。

**盘中**（09:10–16:00，服务器上自动录制）
- 全部主板股票每 60 秒一张快照：集合竞价、五档盘口、涨停封单、炸板，以及盘后固定价格交易。
- **新增**：宽基 ETF、主要指数、恒指期货、黄金、原油，每 60 秒一次；股指期货（IF / IH / IC / IM）每分钟读一次中金所公布的文件，这个文件大约 5 分钟才更新一次；富时 A50 和离岸人民币每天下午取一次当日的 1 分钟线（这个来源从服务器访问不稳定，有的日子可能缺）。用来观察"国家队是否在买宽基"之类的盘中状态。
- 7×24 新闻（同花顺、东方财富、财联社），按规则判断每条新闻利好还是利空、影响哪些股票和行业。规则判断不了的交给大模型。最后对照持仓分级告警：
  - **P0**：持有的股票出了利空；
  - **P1**：宏观或政策利空波及持仓所在行业；
  - **P2**：观察池里的股票有消息，或者有利好但我们没有持有。

## 研究纪律（Pulse 的核心）

1. **只用当时能拿到的数据**：信号只用已经收盘的 K 线，次日开盘才成交；行业成分、市值都按当时的数据算。
2. **先写标准再看结果**：每批实验先写预注册文档，写明指标和通过门槛，然后才运行。结果不好看也照实记录。
3. **和公平的对手比**：不和大盘比，而是和同一天、同市值、同波动的随机股票比，避免把"小盘股效应"误当成本事。
4. **成本按真实账户算**：每笔 5 万元；佣金万 5；印花税万 5（卖出）；过户费万 0.1；滑点每边 5 个基点。一买一卖约 0.25%。
5. **统计要诚实**：持有多天的收益前后重叠，必须用块自助法算 p 值。我们曾因此重算过以前 4 个实验的全部 p 值（E082）。
6. **失败也保留**：一个方法在这段行情里失败，换一种行情可能有效。账本里每一条都写着"什么情况下值得再试"。

## 快速开始

```bash
python scripts/pulse.py install   # 安装依赖并生成前后端契约（首次）
python scripts/pulse.py dev       # 后端 :8000 + 前端 :5173
```

打开 http://127.0.0.1:5173 。需要 Python 3.12+ 和 Node 22.12+。Windows 也可以运行 `start.ps1`，macOS / Linux 用 `./start.sh`。

默认是 `SIM` 演示模式，用内置的模拟行情。要用真实数据，先回填历史：

```bash
python scripts/pulse.py sync --kind backfill --years 3 --wait-hours 24   # 全市场日线（新浪），被限流时等待后续传
python scripts/pulse.py sync --kind daily                                # 收盘后增量
python -m backend.app.warehouse.lhb --years 3                            # 龙虎榜
python -m backend.app.warehouse.boards                                   # 行业与概念成分
```

所有抓取都按来源限速；一旦被拒绝访问就立即停止，不重试、不绕过。

## 盘中录制与新闻告警

```bash
python -m backend.app.warehouse.intraday run       # 主板 60 秒快照、封单、分钟线
python -m backend.app.warehouse.intraday_ext run   # ETF、指数、期货、A50、汇率、黄金
python -m backend.app.warehouse.news run           # 7×24 新闻
python -m backend.app.warehouse.news_alerts run    # 新闻 → 个股 → 持仓告警
```

大模型的密钥只从环境变量 `OPENAI_API_KEY` 或本机受保护的文件读取，不写日志、不进仓库。没有密钥时只用规则判断。服务器上用 `scripts/set_openai_key.ps1` 写入密钥，它在隐藏提示符下输入，不经过命令行。

## 给 AI Agent 用

```bash
claude mcp add --transport http pulse http://127.0.0.1:8000/mcp
curl http://127.0.0.1:8000/llms.txt
```

同一个能力注册表（`backend/app/agent/capabilities.py`）生成 REST 清单、MCP 工具和 `llms.txt`，共 32 项：盘中行情、选股、回测、战法、推荐、数据仓状态等。

服务器上用计划任务运行。网页服务只监听本机端口，不对公网开放，从自己的电脑通过 SSH 隧道访问。步骤见 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。

## 数据诚实性

- 每个接口响应都带数据来源、截止时间和覆盖率。缺失的数据显示为 `—`，不填 0，也不估算。
- 回测逐笔按日线计算：次日开盘成交，一字涨停板买不进就放弃，T+1，跌停封死时顺延卖出，按 100 股整手。所有假设都写在每次回测的结果里。
- 已知局限：数据仓只含仍在上市的股票（有幸存者偏差）；历史 ST 状态未知；成交额为估算值。
