# Pulse 重建规格（总纲）

> 版本 1.0 · 2026-11-10 · 状态：待用户确认 10 卷中标 ★ 的三项后开工。
> 这是一份可以直接照着从零重写的规格。实现者不需要、也不应该阅读旧代码；唯一的例外是迁移车道，它读取旧数据与旧产物并把旧脚本当黑盒运行（08 卷）。

## 1. 一页读完

**要建的是什么。** 一个 A 股选股平台：把消息面、情绪面、资金面、技术面的信息采集进来并统一成信号，据此给出按顺序排列的推荐；点进任何一只股票能看到完整的技术分析、买卖点与持有计划；每条建议都在同一套仿真环境里被前向验证；所有策略在一个库里分类、比较、晋升或休眠，并持续吸收新的想法。

**对现有代码的裁决。** 重写。现有代码的问题是结构性的：两套互不相通的系统、至少 15 套成交与计分逻辑、11 类存储而没有统一数据模型、三套互不相通的契约。局部修补消除不了这些。继承的是数据、52 条验证过的领域规则、92 条实验台账与前向记录（01 卷）。

**对“要不要升级数据库”的回答。** 现在不需要。数据量很小；缺的是统一的数据模型。先统一命名、单位、时间语义、校验与多源裁决，物理层用 Parquet 数据湖加一个嵌入式状态库，藏在端口后面；出现可观测的触发条件时再换成服务型数据库（03 卷第 11 节、04 卷）。

**最重要的一条现实。** 到今天为止，被本项目证据支持的是“排序”和“风控”，不是“买点”：追涨打板、单指标技术买卖点、追近期冠军策略、按市场状态选策略，在真实成交仿真下全部不成立；多因子排序、避开最差的股票、看净值降仓成立。所以这份规格的做法是：用户想要的功能全部提供，但每个结论都带证据等级，并在同一套环境里被持续检验；能影响推荐排序的权力，只发给通过检验的策略。

## 2. 十二条原则（03 卷详述）

1. 一个事实只存一处。
2. 契约是模块之间唯一的耦合。
3. 函数式内核，命令式外壳。
4. 时间是一等公民：任何决策只能看到当时已经可用的数据。
5. 未知是一个值，不是 0。
6. 一切带版本，只追加。
7. 一个撮合器，一本账。
8. 展示给用户的每个结论都带证据等级。
9. 大模型只出判断，分数由代码算。
10. 响亮地降级：数据不新鲜就显示不新鲜。
11. 能力只定义一次，三处暴露。
12. 按小机器设计，按接口升级。

## 5. 证据等级（全平台统一用语）

| 标签 | 含义 | 对应的策略状态 |
|---|---|---|
| 已验证 | 通过回测门槛并有足够的前向记录 | 试用、正式 |
| 检验中 | 通过回测门槛，或版本已冻结并在前向记录中 | 候选、影子、旧制前向 |
| 未检验 | 已登记或刚导入，还没有按新门槛评估 | 提出、已登记 |
| 已证伪 | 预注册的判定明确不成立；保留规格与结果 | 已证伪 |

状态、标签与权限的完整对应只有一张表：06 卷第 5.1 节。上线第一天没有任何策略是“已验证”，这是证据的真实状态。

## 6. 这份规格没有做的事

- 没有修改任何代码，没有运行旧系统的测试，没有连接服务器。
- 外部调研多数只读到摘要或搜索结果片段；凡进入规则表、费用表与默认阈值的事实，都列在 09 卷第 7 节，须在开工的第一个里程碑核对原文。
- 技术组件的版本号没有二次核实，实现时以官方发布页为准。
