## 1. 结论

1. **设计内容大部分采纳**，尤其是时间语义、T+1 库存账本、"未成交也进机会账本"、固定入场比较退出、多轴状态，以及"7–10 月是开发集不是测试集"。这些是本仓库的真实缺口，或已有做法的更严格版本。
2. **"全新仓库、不引用旧代码"不建议照做**。文档自己写了"完全重写必然更好"需要证明（2.2 节最后一行）。当前仓库有 706 个后端测试、一个正在服务器上录制的盘中记录器、带日期的申万行业、真实上市日期、50 条实验台账，数据资产和验证过的语义都在这里。建议在本仓库内**按文档的契约新建内核**（contracts / domain / portfolio / execution），旧模块逐个迁到新契约下，迁完一个删一个。这也和你 11-01 的决定一致："在当前仓库演进，先锁 P1 四个契约再并行"。
3. **需要你决定两件事**（见第 6 节）：仓库策略，以及是否在明天开盘前给记录器加 15:05–15:30 盘后时段。

## 3. 文档指出的、本仓库确实缺的（建议采纳）

1. **盘后固定价格交易（F20 / C12 / E19，15:05–15:30）**。文档称 2026-07-06 起扩展到全部主板 A 股（未核验）。旁证：同一规则把主板 ST 涨跌幅从 5% 改成 10%，本仓库的 `st_like` 正是在 2026-07-06 之后失效，两者对得上。记录器现在 15:04 收盘快照后就不录行情，盘后时段完全没有数据。
2. **时间语义**（9.4 节）：event_time / published_at / received_at / available_at，AS_OBSERVED 与 AS_PUBLISHED 两种模式。本仓库只有"日线收盘后决策、次日开盘成交"这一种隐含约定，盘中数据湖（P1）必须按这个做。
3. **T+1 库存账本**（8.5 节）：total / sellable / acquired_today / reserved。现在的回测引擎 `simulate` 按持有天数卖出，没有单一账户真值，也没有"可卖量"概念。做 T 和多策略共用资金之前必须有它。
4. **未成交进入机会账本、成交条件收益**（10.5 节、C05）。现在涨停开盘的信号直接剔除（`blocked`），统计里看不到"买不到的收益"。
5. **固定入场、只换退出**（E17）。现有退出规则（ExitRules 十几种）是分别测的，没有在同一批成交上做过对比；拉萨持仓退出也因为没有"按标记卖出"的规则，组合回测只做了入场过滤。
6. **多轴状态**（7.1 节）。线上 Pulse 现在只有一个"熊市模式"开关，不能表达"大盘弱、某主题在扩散"。
7. **14:50 测试改成看账户增益，不看 AUC**（C09 末句）。E049 给了 AUC 和前 20 名收益；E051 的账户级结果是零增益（主书与这些股票不重叠），应在短线账本上重测。
8. **因子生命周期状态**（提出 → 可计算 → 研究通过 → 影子 → 启用 → 休眠 → 退役）比登记簿现在的 active / weak / dormant / error 更细，且要求记录全部搜索族的试验数。

## 4. 不同意或需要修正的地方

1. **全新仓库**：理由见第 1 节第 2 条。文档的 monorepo 目录（apps/、packages/）可以在本仓库里按新目录建，不需要新仓库。
2. **PostgreSQL 首发**：服务器是 2 核 8 GB 的 Windows，现在没有任何数据库服务。账本和任务表在单写进程下用 DuckDB 或 SQLite 也能满足"事务 + outbox"。建议先用嵌入式库实现同一套表结构，接口不变，等真有多进程并发写再换 PostgreSQL。
3. **补丁 C 的措辞**：文档说 max(买一ₜ, 买一ₜ₊₁) "不能称作保守且必然正确的事实"（10.3 节）。同意：仿真器 v2 应把它作为一个情景，同时输出"乐观 / 基准 / 悲观"三档成交区间，而不是单一结果。这是对我们 6.3 节规则的修正，采纳。
4. **期间命名**：文档要求 2026-07~10 不得称为测试集。台账里 SELECT（7–8 月）、VERIFY（9–10 月）都已被反复查看。建议改名为"开发集 A / 开发集 B"，真正的样本外从各版本冻结日起算（主书已于 11-01 冻结）。
5. **编号冲突**：文档的 P0–P5、E01–E30 与本仓库的 P0–P4、E001–E050 重名。引用文档实验时加前缀 `D1-E01`，阶段用 `D1-P0`。

## 7. 拍板（2026-11-02，用户）

- **仓库**：不新建仓库。在本仓库内按设计 1.0 的契约新建内核，旧模块逐个迁移。
- **数据库**：不上 PostgreSQL。2 核 8 GB 服务器坚持嵌入式数据库 + Parquet，表结构与文档保持一致。
- **期间口径**：2026-07~10 正式更名 DEV（开发集；SELECT = DEV_A，VERIFY = DEV_B）。11 月起的前向记录是真正的样本外（OOS，自 2026-11-02）。已写入 `scripts/lab/harness.py` 与台账表头。
- **采纳**：盘中数据湖和核心表落地 8 个时间字段；全账户唯一的 T+1 库存账本（总量与可卖量分开）和机会账本（排队未买到的目标单）；仿真器 v2 输出乐观 / 基准 / 悲观三档；卖法实验固定同一批入场；市场状态按指数、广度、风格、情绪、题材分别估计。
- **盘后时段**：批准并已部署（提交 f70f894）。15:05–15:30 静态池与热点池每 60 秒，全主板 15:05:05 / 15:15:00 / 15:30:05 各一次，原始文本全部保留；热点分时从 15:03 移到 15:31，避免挡住盘后网格。
- **拉萨与一日游席位、14:50 预测**：主书与龙虎榜短线池几乎不重叠（E051），不在主书上测持仓退出。三者归档为以后短线 / 题材账本专用的入场过滤与卖出信号。
