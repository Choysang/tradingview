# E082：用块自助法重算 E058–E070 中持多日的 p 值（2026-11-08）

> 本文件第 0–4 节在重算之前写定，结果写在第 5 节。

## 0. 问题

`sameday_base._boot` 先按"有信号的交易日"汇总，再对这些交易日独立重抽样。每笔持有 h 日（5/10/20），相邻决策日的持有窗口重叠 h−1 天，所以每日超额是自相关的。独立重抽样低估了方差，p 值偏小。

E081 复核时发现：20 日急跌型超跌持 10 日，PRE 的 p 从 0.007 变成块自助的 0.175。见 `2026-11-08-os20-shock-rebound-preregistration.md` 第 0 节。

## 2. 新方法（`sameday_base._boot_block`）

1. 段内所有交易日排成一行，包括没有信号的日子。每天记下信号的超额之和 Σe 和信号数 k；没有信号的日子都为 0。
2. 移动块：块长 = 持有天数 h，单位是交易日。随机抽出连续的块，拼接到原长度。
3. 每次重抽样的均值 = ΣΣe / Σk，与原方法一样按信号数加权。Σk = 0 的抽样丢弃。
4. p = 重抽样均值 ≤ 0 的比例；抽 2,000 次，种子为 `SEED + h`。
5. 只有设置环境变量 `LAB_BOOT_BLOCK=1` 时才计算，结果另存为 `*_blk` 字段（`p_boot_blk`、`p_all_blk`、`p_sv_blk`、`p_svi_blk`、`p_svs_blk`）。原字段的算法和随机数序列都不变。

## 5. 结果

运行于 2026-11-08。脚本 `scripts/lab/reeval_block.py`；输出在 `.work/lab/main/reeval_block/`（`summary.json`、各实验的新结果文件、日志）。五个脚本都正常退出，`.work/lab/main` 里没有其他文件被改动，原结果文件都已恢复。

### 5.1 复现核对，以及对第 3 节的一处修正

**确定性字段**（次数、天数、均值、胜率、各段收益、匹配超额）在五个输出中**完全一致**，只有一处例外，见第 3 条。所以信号与第一次运行完全相同。

**依赖随机数的字段**（`random`、`excess`、`p_mc`、`p_boot`、`p_all`、`p_sv`、`p_svi`）与原文件不同：p 值最多差 0.058，`random` 最多差 0.17 个百分点。

1. **原因**：Polars 的 `group_by` 不保证输出顺序，而 `_mc` 和 `_boot` 抽随机数时是按这个顺序遍历交易日的。所以即使种子固定，同一份代码运行两次，结果也不同。在同一进程里连续调用两次 `evaluate` 已验证了这一点。差异的大小与蒙特卡洛误差相符：1,000 次抽样时，单个 p 的标准误约 0.016。
2. **对第 3 节的修正**：第 3 节要求"原 p 完全一致"，前提是原方法可以复现，但这个前提不成立。所以复现标准改为：**确定性字段必须完全一致**（成立），随机字段只报告差异大小。这项修正不影响 `*_blk`：块自助的随机数按日期位置对应，与遍历顺序无关，结果是确定的。
3. **例外：E058 的 12 个 Newey-West t 值**。`sequoia_audit.rank_ic` 对 `group_by` 的结果直接计算 Newey-West t，没有先按日期排序，所以 t 值算在顺序被打乱的序列上，自相关修正失效，每次运行也不同。已修正为先排序，见 5.3。

**已修复**（以后的运行可以复现）：`sameday_base.evaluate`、`evaluate_matched` 和 `cond_reversal.with_score_cell` 都改为先按日期排序再抽样，`sequoia_audit.rank_ic` 也先排序。在真实数据上连续运行两次，结果完全相同，并加了回归测试。

### 5.2 显著个数：原方法与块自助

下表的旧 p 来自本次重跑的同一次运行，所以与新 p 可以直接比较。"正"指 p < 0.05（显著为正），"负"指 p > 0.95（显著为负）。

**可靠性**：段内交易日数除以持有天数少于 10，也就是不到 10 个块时，块自助不可靠。
- PRE 的所有持有期都可靠；
- DEV 只有持 5 日可靠（约 77 个交易日 / 5 = 15 个块）；
- DEV 持 10 日、20 日的结果标 \*，只报告。

| 实验 | PRE 正：旧 → 块 | PRE 负：旧 → 块 | DEV 持 5 日 正 / 负：旧 → 块 | DEV\* 持 10/20 日 正：旧 → 块 |
|---|---|---|---|---|
| E058 Sequoia-X（72 / 18 / 54 行） | 5 → 1 | 33 → 16 | 0 → 0 / 7 → 6 | 0 → 0 |
| E060 出场（12 / 4 / 8 行） | 5 → 4 | 1 → 0 | 1 → 1 / 1 → 1 | 2 → 2 |
| E060 背离（27 / 9 / 18 行） | 0 → 0 | 3 → 2 | 3 → 2 / 2 → 1 | 2 → 1 |
| E062 匹配基准（495 / 165 / 330 行） | 32 → 21 | 211 → 173 | 23 → 13 / 54 → 54 | 54 → 31 |
| E070 条件反转（98 / 49 / 49 行） | **7 → 0** | 31 → 25 | 1 → 0 / 18 → 12 | 14 → 10 |

- **可靠的格子里，没有任何一项由块自助变成显著为正。**
- 有 6 项刚好跨过"显著为负"的线，全部在 E062 的 DEV 持 5 日，变化只有 0.01–0.04。例如 `pb:m_ma_golden` 的 p_sv 从 0.936 变为 0.966。
- 不可靠的格子里（DEV 持 10 日、20 日），共有 20 项变显著，例如 `pb:low_volatility` DEV 持 20 日从 0.26 变为 0.02。原因是一次抽样只有 3–4 个块，移动块在序列两端抽到的少，中段的分量被放大。这些都不采用。

### 5.5 结论

1. 持多日的结果，原方法的 p 值普遍偏小。在 PRE 中，E070 显著为正的 7 项全部消失，E058 从 5 项降到 1 项，E062 从 32 项降到 21 项。
2. 所有预注册判定都不变：E062 仍然 0 个存活，E070 的 H1 仍不成立、H4 仍成立。以前的结论之所以站得住，是因为它们大多是"不成立"，或者依赖的是极端的 p（例如 H4 的 1.0）。
3. 以后的检验：
   - 持多日的结果一律用块自助法，块长等于持有天数；
   - 块数少于 10 的格子，p 只报告，不用于判定；
   - DEV 只有 82 天，持 10 日以上的 DEV p 值不能用来下结论。
4. E079 第 7.4 节的描述性 p（主书买入相对全池 DEV p 0.007）用的是旧方法，它不参与判定，这里不重算。
