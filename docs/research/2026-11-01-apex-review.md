# 对“ashare-apex 重构方案”的评估与分阶段计划

> 日期：2026-11-01 晚。依据：第 6~7 轮台账 E027~E045、仓库现状（本文第 2 节逐项核对）、本轮对龙虎榜“拉萨天团”主张的现场检验（第 3 节）。
> 状态：方案，未动代码。需要你在第 6 节拍板。

## 结论先行

- **方向对**：A 股短线的超额在盘中（竞价轨迹、封单、炸板瞬间、分时买卖点），旧研究只有日线，这是事实。录制器明天第一次运行，补的正是这个缺口。
- **瓶颈是数据，不是代码架构**：盘中录制数据目前为 0 天。B1~B6、S1~S5、T1/T2、盘中做 T 强化学习，在攒够 20~60 个交易日之前都无法验证。现在让多个 Agent 并行写完，得到的是一大批没有检验过的代码。
- **不建议另起新仓库重写**：
  - 方案里的微内核、卡带、时间锁，现仓库大多已有雏形：
    - 仓库每张表带 `ingested_at`；
    - 因子插件目录 `backend/app/factors/plugins/`；
    - 战法库有 52 套；
    - 撮合引擎已处理成本、一字板、涨跌停；
    - 龙虎榜 3 年数据、前端、Agent 接口都在。
  - 缺的是三块：盘中数据湖（带 `known_time`）、盘中触发器状态机、按真实封单排队的撮合 v2。
  - 建议在现仓库里按卡带协议新增目录，逐块替换旧部分。已验证的资产（净值均线降仓、11 月前向记录）继续保留。
- **“胶水代码”的判断要分开看**：
  - 上市天数是数据 bug，任何架构都要修。另外 `securities` 表其实有真实的 `list_date`，可以改用它，比现在的近似更准。
  - 净值均线降仓不是胶水：参数矩阵 12 格全部降低回撤（E040），它已冻结为 11 月的正式方案。
  - 共线账本切换已经证伪（E042），不会继续加。
- **文中的数值“铁律”大多没有出处**，要逐条检验。第 3 节检验了一条：描述成立，但按龙虎榜的公布时间去执行，几乎赚不到。

## 3. 现场检验：“拉萨天团包揽买方前五 = 见顶，次日清仓、严禁买入”

数据：主板、非 ST，龙虎榜买方前五里拉萨营业部的席位数，2023-11~2026-10。

| 拉萨席位数 | 样本 | 次日开盘跳空 | 次日开盘买、第三日开盘卖（扣成本） | t |
|---|---|---|---|---|
| 0 | 21,136 | +0.82% | −0.70% | −7.1 |
| 1~2 | 7,182 | −1.85% | −0.92% | −6.5 |
| 3 个以上 | 4,367 | **−3.13%** | −0.98% | −4.9 |
| 当日涨停且 3 个以上 | 490 | −1.07% | −1.48% | −2.5 |

- 描述成立：3 席以上时，次日开盘平均低 3.1%，没有拉萨席位时是高 0.8%。
- 但赚不到：龙虎榜收盘后才公布，最早次日开盘才能卖，跳空已经发生。按次日开盘买入的口径，3 席以上组只比 0 席组差 0.3 个百分点（当日涨停的子集差 0.8 个百分点），而且三组都是负的。
- 结论：它可以当“别买”的弱过滤条件，不是能赚钱的卖点。要利用这个跳空，得在收盘前判断，需要盘中数据或其他来源。

文中其余的“铁律”（量化席位次日 9:30~9:35 必砸、09:20 撤单率超过 85% 即诱多、封单衰减 70% 就砸等），都按这个方法逐条检验，数字以检验结果为准。

## 4. 分阶段计划（建议）

**P0：本周，用现有日线和龙虎榜**
- 席位基因：一日游席位含量、拉萨含量、机构的真假，按“次日开盘可执行”的口径检验，只作过滤和风控。
- 筹码结构：换手加权的成交分布，计算单峰集中度和距上方套牢峰的空间；左峰天量墓碑线。
- 缠论三买和威科夫 Spring 的日线版，进入传统战法统一检验（按 PRE 选卖法）。
- 上市天数改用 `securities.list_date`。
- 查一下真实自由流通股本的数据源。

**P1：录制第 1~2 周**
- 盘中数据湖：把录制器的输出转成带 `event_time`（交易所时间）和 `known_time`（我们收到的时间）的表，提供一个“只能看 known_time ≤ 当前时钟”的读取接口。
- 撮合 v2：按封单排队成交（补丁 C 规则）。
- 触发器卡带协议，和你稿里的接口一致：`on_snapshot(snapshot, watchlist, positions) -> list[ActionSignal]`。先实现 B1、B3、S1、S3，在已录制的日子上逐日回放，只做纸面记录。
- 录制器加入可转债。

**P2：录制满 20~60 天**
- 用真实封单校准排队成交率，检验各个触发器；做 T1/T2 规则基线；叙事和辩论 Agent 只做前向检验。

**P3：录制 60 天以后**
- 盘中做 T 强化学习（以 T1/T2 为基线）、截面注意力模型，以及带 WebSocket 推送的盘中驾驶舱前端。

并行开发：P1 的契约（数据湖读取接口、`ActionSignal`、触发器协议、撮合 v2）定下来以后，再按你稿里的 6 条工作流分到多个会话并行。每个会话只写自己的目录。
